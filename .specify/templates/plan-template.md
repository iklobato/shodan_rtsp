## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Gates from `.specify/memory/constitution.md`. Each one is answered yes or no, and a
no blocks the plan until it is fixed or justified in the Complexity Tracking table.

| # | Gate | How to answer it |
|---|------|------------------|
| 1 | Authorized targets only | Does every new network egress path name the target set it can reach, and is that set the lab or a target with written authorization? |
| 2 | Read-only proof | Do the CVE modules pull at most one frame, and write nothing to the target? |
| 3 | Python SOLID | Does every function live in a class, at most 3 params, at most 20 lines, no `elif`, collaborators injected, own exception types? |
| 4 | Tests that can fail | Does each new behavior carry a test that fails when the logic breaks, testing the failure path, with Fakes rather than Mocks for IO? |
| 5 | Lab-verified | Is there a real run in the lab for this front, with the raw output recorded, and is every unmeasured value labelled a placeholder? |
| 6 | Recorded decisions | Does the change contradict a decision in `docs/decisions/2026-11-11-shodan-rtsp-prod-ready.md`? Unlimited retention and the absent scope gate are accepted risks, so a change that deletes stored data or widens reach must raise it, not act. |
| 7 | Migrations | Is the schema change a versioned Alembic migration, live-safe, with a rollback path? |
| 8 | Smallest diff | Is there a one-line IN/OUT scope, and does every edit trace to it, with no drive-by refactor of untouched code? |
| 9 | No new dependency | Does the change avoid adding a dependency, framework or build tooling without an explicit decision? |
